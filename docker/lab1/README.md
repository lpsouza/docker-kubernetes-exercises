# Lab 1: Docker CLI Basics

This hands-on lab guides you through the fundamental Docker CLI commands. You will pull an official Nginx image, run it in the background with port mapping and environment variables, modify its default page, and inspect its runtime state.

## Prerequisites

Ensure that you have Docker installed and running on your local machine.

## Steps

### 1. Pull the Official Nginx Image

First, retrieve the official Nginx image from Docker Hub.

```bash
docker pull nginx:latest
```

To verify that the image was successfully downloaded, list the images available locally:

```bash
docker images
```

Look for `nginx` in the list of images.

### 2. Run the Container in Detached Mode

Start a new container from the Nginx image. The container must run in detached mode (`-d`), map host port `8080` to container port `80` (`-p`), define a custom name (`--name`), and inject a generic environment variable (`-e`).

```bash
docker run -d \
  -p 8080:80 \
  --name nginx-lab \
  -e ENV_TYPE=development \
  nginx:latest
```

To confirm the container is running and check the port mapping, list the active containers:

```bash
docker ps
```

You can also test accessing the Nginx server by opening your web browser and navigating to `http://localhost:8080` or running the following command:

```bash
curl http://localhost:8080
```

### 3. Modify the Index Page Using Shell Access

Access the container's interactive shell to update the default index HTML page.

First, open a bash session inside the running container:

```bash
docker exec -it nginx-lab bash
```

Inside the container, modify the default Nginx welcome page:

```bash
echo "Hello from Docker Lab!" > /usr/share/nginx/html/index.html
```

Exit the container session:

```bash
exit
```

Alternatively, you can run the modification command directly from your host system without entering the interactive shell:

```bash
docker exec nginx-lab sh -c 'echo "Hello from Docker Lab!" > /usr/share/nginx/html/index.html'
```

Verify that the changes were applied successfully:

```bash
curl http://localhost:8080
```

The output should display `Hello from Docker Lab!`.

### 4. Inspect Container Logs and Resource Usage

Monitoring is key to managing containerized applications.

To view the stdout and stderr logs generated by Nginx:

```bash
docker logs nginx-lab
```

To stream the logs in real-time as new requests arrive:

```bash
docker logs -f nginx-lab
```

To inspect the real-time resource utilization (CPU, memory, network, and disk I/O) of the container:

```bash
docker stats nginx-lab
```

Press `Ctrl+C` to exit the stats stream.

To view detailed configuration metadata of the container in JSON format:

```bash
docker inspect nginx-lab
```

### 5. Cleanup

Once you have completed the lab, stop and remove the container to free up host resources.

Stop the container:

```bash
docker stop nginx-lab
```

Remove the container:

```bash
docker rm nginx-lab
```

Verify that the container is no longer present:

```bash
docker ps -a
```

## Troubleshooting

Here are common issues you might encounter and how to resolve them:

- **Port 8080 is already in use**: If another process is using port `8080`, the container will fail to start. You can map Nginx to a different host port (e.g., `-p 8081:80`) or stop the conflict-causing service on the host.
- **Docker daemon not running**: If you receive a connection error, verify that the Docker service is running on your host machine.
- **Container name conflict**: If a container named `nginx-lab` already exists, Docker will report a conflict. Stop and remove the existing container using `docker rm nginx-lab` before retrying.
